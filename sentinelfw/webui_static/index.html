Protected Management IPs
IPs and networks that are never banned, killed or redirected — your laptop, jump hosts and admin ranges. Private LAN ranges are protected by default; add or remove entries below.
Integrations & Console TLS
Suricata and ClamAV are pulled in automatically at daemon start where the host allows it (Linux + root; elsewhere a manual note is logged). The Go service supervisor builds and health-checks the sentinelgated daemon when a Go toolchain is present. Console TLS terminates on a bring-your-own certificate — sfwctl tls-gencert generates a self-signed pair for lab use.
—
—
DNS Security
A filtering DNS forwarder. Point the host (or DHCP clients) at this machine's DNS and every query is checked against your domain blocklists before being forwarded upstream — blocked domains return the sinkhole address. Works even without hosts-file elevation.
—
—
Fleet (Central Relay)
Enable this console as a fleet relay, then run agents on your other SentinelFW hosts: python sfwctl.py fleet-agent --relay http://THIS-HOST:443 --key YOUR-KEY. Agents report bans, threats and recent events every 30 s and pull the shared IP blocklist back down to their own lists/fleet_shared.txt.
—
Log Vault — Sealed Chain + FLUSH
Seals the event log into chained, HMAC-signed blocks (Merkle root + previous-block hash — blockchain-grade tamper evidence: edits, deletions and forged blocks are all detectable). FLUSH deletes every stored log artifact at once: events.jsonl, the audit chain, the vault chain, the intel cache and all forensic PCAPs. Type FLUSH to confirm.
—
—
Operations Safety & Forensics
Commit-confirm stages config changes and auto-reverts them if you do not press CONFIRM within the TTL — protects against locking yourself out. The PCAP ring keeps raw packets in memory and dumps a Wireshark-readable capture around every alert. The persistence watch alerts when cron / systemd / Run keys / autostart entries change.
—
—
Console Security & Learning Mode
Session-cookie login with CSRF protection and automatic lockout is active. Add a second factor (TOTP, RFC 6238) for the console, enable learning mode to record detections without enforcing bans, and inspect the tamper-evident audit trail.
—
—
Antivirus — ClamAV
System-wide malware scanning through the local ClamAV engine. Signatures auto-update daily (freshclam, ~03:30), scans can quarantine findings into the SentinelFW quarantine store, and every result is written to the event log.
—
—
AI Threat Analyst (Sarvam-105B)
Agentic threat identification: consolidated evidence (bans, vectors, traffic, VT, IDS events) is assessed by Sarvam's flagship 105B model. High-risk unknown IPs are auto-analyzed (rate-limited); any IP can be analyzed on demand via right-click → AI THREAT ANALYSIS. Assessments are stored in the local SQLite database.
